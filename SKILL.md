# Scientific Paper Writing — Unified Methodology

Combining two complementary foundations:
- **Alley (bottom-up craft)**: sentence-level precision, energy, organization, revision workflow
- **Lebrun (top-down strategy)**: reader psychology, publishing ecosystem, paper architecture

---

## Core Methodology — The Unified Two-Layer Model

These two layers are applied **iteratively**: start with **Strategy, then Craft, and iterate between them as needed**. Writing is not a linear pipeline — while auditing sentences you may discover structural problems (bait-and-switch, missing gap statement), sending you back to Strategy to fix the argument before polishing prose.

### Layer 1: Strategy (Lebrun)

Before writing a word, fill in this **Reader Analysis Worksheet**. It forces you to answer the strategic questions that govern every subsequent craft decision.

#### Reader Analysis Worksheet

```
=== TARGET VENUE ===
Journal/Conference: _______________
Word/page limit: _______________
Style conventions: (structured abstract? section format? citation style?)

=== PRIMARY READER PROFILE ===
Who is the typical reviewer?: (subfield specialist? generalist? methodologist?)
What do they already know?: (domain basics? related techniques? prior work?)
What MUST you explain?: (gap, key assumption, novel method)
What are their biases?: (preferred methods? competing paradigm? halo effect risk?)

=== THE KNOWLEDGE GAP ===
What was known BEFORE this work?: (1-2 sentences)
What SPECIFIC question remained unanswered?: (1 sentence)
How does your work answer it?: (1 sentence — this is your one-sentence contribution)

=== READER PSYCHOLOGY CHECK ===
Does the intro open with a positive, specific statement? (avoid "In recent years..." — see W4)
Are counter-arguments acknowledged early? (confirmation bias management)
Will the reader see the gap before you state it? (if yes, state it earlier)
Is the title specific enough to survive a search results list? (see W6)
```

Answering these questions takes 15 minutes. It prevents weeks of misdirected drafting.

**Common failure mode:** Skipping this step and starting with "I'll just write the Methods first" — leads to an Introduction that doesn't match the Results, an Abstract written before the paper is complete, and a title that doesn't distinguish the work.

**When to revisit Layer 1:** If at any point during crafting you discover that the gap statement doesn't align with the actual findings, or that the target journal's conventions conflict with your intended structure — stop crafting, return here, and revise the strategy before continuing.

### Layer 2: Craft (Alley)

With the strategy as your foundation, craft each sentence and paragraph. **If craft reveals strategy gaps, loop back to Layer 1** and refine the argument before continuing.

1. **Energy** — Strong verbs, concrete nouns, no deadwood
2. **Flow** — Begin with familiar, end with new; use transitions
3. **Organization** — One paragraph, one point; deductive or inductive as appropriate
4. **Emphasis** — Key findings in stress positions (end of sentences, paragraphs, sections)
5. **Revision** — Print, read aloud, audit, fix

### Sustaining Reader Attention

> "Attention is the reader's most limited resource. You must earn it at every paragraph." — Lebrun, SW3 Ch5

Three techniques, working together to keep the reader engaged from abstract to conclusion. Apply these during drafting and verify during revision.

#### 1. Forward Movement

Each sentence builds logically on the one before. The reader should never need to re-read a sentence to understand how it connects.

- **No backtracking:** If you need to clarify a previous point, rewrite the previous point — don't add a clarification sentence
- **No digressions:** Every sentence advances the argument or provides necessary evidence. If a sentence can be removed without losing the logical chain, it should be
- **Check:** Cover each sentence after reading it. Does the next sentence follow naturally? If not, the logical bridge is missing

#### 2. Suspense (Information Gap)

Create a controlled "need to know" that pulls the reader forward. The Introduction does this explicitly (knowledge gap), but the technique works throughout:

- **At the end of each section:** Hint at what comes next ("Having established X, we now test whether Y improves...")
- **In Results:** State the finding first (deductive), then give the evidence — the reader wants to see the proof
- **In Discussion:** Raise a question, then answer it. The pause creates engagement
- **Warning:** Suspense must be genuine. Fabricated uncertainty frustrates readers

#### 3. Relief Points (Visual Rest Stops)

Attention naturally flags every 3-5 paragraphs. Plan your structure around this rhythm.

- **Short paragraphs** (3-5 lines) give the reader visual and cognitive rest
- **Headings** break the text into predictable units — each heading is a reset point
- **Figures and tables** are the most effective relief points: they convey evidence faster than text
- **Bulleted lists** (sparingly) break up dense prose
- **Check:** Read your paper and mark every paragraph boundary. If any stretch of 5+ paragraphs has no heading, figure, or list break, insert one

#### Checklist

- [ ] Can each section be understood by reading its first sentence of each paragraph? (Forward movement)
- [ ] Does the Introduction create a clear information gap that pulls the reader toward Results?
- [ ] Are there visual rest stops (headings, figures, short paragraphs) at least every 5 paragraphs?
- [ ] Have you identified and removed all digressions?
- [ ] Do transitions at section ends hint at what comes next?

### How to Use This Skill: Recommended Reading Order

The workflows are standalone, but for a full paper they work best in a specific sequence with iterative cycles.

#### Starting from Scratch (no draft)

```
1. Fill in Reader Analysis Worksheet (Layer 1)     →  15 min
2. Workflow 1: Write Hard Parts First               →  Methods → Results → Discussion
3. Workflow 4: Introduction                          →  Write after Results are clear
   │   └── If gap doesn't match findings → back to Layer 1
4. Workflow 5: Sentence Audit on all sections        →  Energy → Flow → Length
   │   └── If systematic pattern fails → back to Layer 2
5. Workflow 3: Abstract                              →  Write LAST
6. Workflow 6: Title                                 →  Last step before submission
7. Workflow 7: Conclusion                            →  Verify alignment with Introduction
```

#### Revising an Existing Draft

```
1. Workflow 2: Revising — Pass 1 (Strategic Audit)  →  Check gap, promise, halo
   │   └── If structural problems → back to Layer 1
2. Workflow 2: Passes 2-4 (Energy → Flow → Paragraph)
   │   └── If systematic pattern fails → back to Layer 2
3. Workflow 5: Sentence Audit on revised sections
4. Workflow 3: Abstract                              →  Update to match new draft
5. Workflow 6: Title                                 →  Verify still accurate
6. Workflow 7: Conclusion                            →  Verify alignment with Introduction
```

#### Quick Check (one section only)

```
1. Navigate to the relevant workflow (W3 Abstract, W4 Introduction, W5 Sentence, etc.)
2. Run its checklist
3. If the checklist exposes a structural problem → go to Layer 1 before continuing
4. If the checklist exposes a craft problem → apply Layer 2 fixes
```

**Key principle:** Each workflow is a loop, not a pass-through. If any workflow reveals a problem at the wrong level (e.g., a sentence audit reveals a missing gap statement), **go back to Layer 1 or Layer 2** before continuing. The loop checkpoints (🔁) at the end of each workflow signal when to do this.

### Visual as Evidence

> "A figure is not decoration. It is evidence. The caption must make the figure self-contained." — Alley / Lebrun (both)

Figures and tables carry the paper's empirical weight. Poor figures undermine strong writing because readers (especially reviewers) inspect figures before reading the text.

#### Principles

1. **Self-contained caption** — The caption must explain what the reader sees without referring to the text. A good test: can a colleague understand the figure's message from the caption + figure alone?
2. **One clear message per figure** — If a figure conveys two messages, split it into two panels or two figures. Readers should know the takeaway within seconds.
3. **Evidence, not decoration** — Every figure must earn its place. If removing it would not weaken the paper's argument, remove it. Never include a figure "because it looks nice."
4. **Standard format** — Use vector graphics (PDF/SVG) for line art, not raster (JPEG/PNG). Follow journal guidelines for resolution, font size (typically 6-8 pt minimum), and color (print-friendly or color-blind accessible).
5. **Place near the relevant text** — A figure should appear in the same page spread as the paragraph that discusses it. Avoid "figure X shows" — instead, state the finding and use the figure as supporting evidence.

#### Common Violations

| Violation | Symptom | Fix |
|-----------|---------|-----|
| **Unreadable at print resolution** | Text too small, lines too thin | Use 6-8 pt font minimum, 1-2 pt line width |
| **Caption is a label, not an explanation** | "Results of experiment 1" | "Temperature dependence of reaction rate: the enzyme denatures above 45°C" |
| **Redundant data** | Same data in table + figure | Choose the format that best conveys the message (table for precision, figure for trends) |
| **Color-dependent meaning** | "Red line shows X, blue line shows Y" (unreadable in B/W) | Use different line styles (dashed, dotted) + labeled directly on the figure |

> **Note:** This skill does not cover figure creation tools (see `nature-figure` for that). The focus here is on figure *strategy* — what belongs in a figure, how to caption it, and how to integrate it with text.

### Key Cases from the Source Books

These cases illustrate how the principles operate in real writing — use them as teaching tools when helping users understand why a principle matters.

| Case | Principle It Illustrates | What Happened |
|------|------------------------|---------------|
| **Challenger Disaster Memo** (Alley L1) | Emphasis position — burying key info in the middle | Engineers warned NASA about O-ring failure below 53°F, but placed the temperature threshold mid-paragraph. The critical finding was structurally hidden. |
| **Solar Power Plant Proposal** (Alley L6) | Begin with the familiar — audience analysis | Original proposal started with technical specs. Revision started with rising energy costs — the problem the review committee already knew. The revised version was funded. |
| **Before/After: Nominalization Fix** (Alley L3) | Energy audit — strong verbs | "An analysis of the data was made by the researchers" → "The researchers analyzed the data" (9 words → 4, passive → active). |
| **Before/After: Topic Position Fix** (Alley L6) | Topic-stress progression | "A new technique for analyzing protein structures using X-ray crystallography has been developed" → "X-ray crystallography, long used to determine protein structures, now offers a new analytical technique." |
| **Reviewer Fatigue — Acknowledging Counter-Arguments** (Lebrun Ch17) | Confirmation bias management | Papers that acknowledge limitations receive more favorable reviews than those that ignore them. Keeps the reviewer in cooperative reading mode. |
| **Four-Sentence Abstract Transformation** (Lebrun Ch14) | Abstract structure | A student's single 200-word paragraph was restructured into the four-sentence template. Reviewers immediately understood the contribution. |
| **ACME Company Report: Misplaced Modifier** (Alley L2) | Structural ambiguity — placing modifiers far from what they modify | "The output of the ACME Company, which has increased dramatically in the past year..." — does "which has increased" refer to "output" or "Company"? Reader cannot tell. Fix: move the modifier next to its referent. |
| **Biomedical Nominalization Overload** (Lebrun Ch3) | Energy audit — noun density | "Implementation of the treatment protocol was performed by the clinical team" → "The clinical team implemented the treatment protocol" (10 words → 6, 3 noun positions → 1). |

### Designing Effective Headings

> "Headings and subheadings act as a roadmap for readers. When they are well-written, the readers can quickly see the strategy of the document." — Alley

**Headings serve two masters**: they reveal the document's logical structure (strategic) and guide skimmers to relevant sections (reader psychology). Both books treat headings as a key tool for reader orientation.

#### Principles

1. **Informative, not generic** — "Results" is a heading, but "Thermal Stability of the Polymer Composite" is an informative heading. Readers skimming for specific content benefit from specific headings.
2. **Parallel at the same level** — if your first subsection is a noun phrase ("Data Collection"), the second should also be a noun phrase ("Statistical Analysis"), not a participial phrase ("Analyzing the Data"). Same grammatical form = same structural level.
3. **Reveal the hierarchy** — use typography and white space to show level (larger font / more space for higher-level headings). A common practice: twice as much space above a heading as below.
4. **Self-contained test** — a good test is whether the headings alone (as a table of contents) reveal the document's organization. If not, revise them.
5. **No single-item subheadings** — if you have only one subsection, remove the subsection heading. A single subheading implies a missing counterpart.
6. **Repeat the heading in the first sentence** — beginning a section by restating its heading (not redundantly, but explicitly) reinforces the section's identity for the reader.

#### Checklist

- [ ] Headings reveal the paper's strategy when standing alone as a TOC
- [ ] Same grammatical form across headings at the same level
- [ ] Headings are informative (specific), not generic
- [ ] Visual hierarchy clear (font size, weight, white space)
- [ ] No orphan subheadings (single item at a level)
- [ ] First sentence of each section reinforces the heading

## Workflow 1: Writing a Paper from Scratch

> **Input**: Raw data, figures, experimental results, target journal identified
> **Output**: Completed first draft + filled Reader Analysis Worksheet

Use when the user has data/figures/results but no draft.

### Step 1: Pre-Writing Strategy

- Determine target journal/venue
- Analyze audience: who will review this? What is their expertise level?
- Define the one-sentence contribution
- Identify the knowledge gap (what was missing before this work?)
- Study 2-3 recent papers from the target journal for style/structure

### Step 2: Write the Hard Parts First

> "Do not write sequentially from introduction to conclusion. Write the sections you find most difficult first, when your energy is highest." — Alley, L10

Recommended order:
1. **Methods** — Most factual, least ambiguous. Write while procedures are fresh.
2. **Results** — Present findings. Use deductive structure: finding first, evidence second.
3. **Discussion/Conclusion** — Interpret results. Acknowledge limitations proactively.
4. **Introduction** — Build from known background → knowledge gap → your approach. Leverage the halo effect.
5. **Abstract** — Four-sentence structure: Background → Gap → Approach → Key Result.
6. **Title** — Specific, searchable, promises what the paper delivers.

**Time management for writing sessions** (Alley L10):
- **Block dedicated writing time** — 90-120 minute uninterrupted blocks, not "write when I find time"
- **Draft quickly, revise slowly** — get words on the page first; don't edit while drafting
- **Write the hard parts when you're fresh** — schedule the most demanding sections (typically Introduction and Discussion) for your peak energy window
- **Step away between draft and revision** — a few hours or overnight separation reveals problems invisible during drafting
- **Set session goals** — "Write the Methods section" not "work on the paper"

### Step 3: Apply Craft Principles

For each section, use the Sentence Audit (Workflow 5 below).

### Step 4: Revise Systematically

- Print the draft and edit with a pencil
- Read aloud to catch awkward phrasing
- Check: does the introduction deliver what the abstract promises?
- Check: is the key finding emphasized (not buried)?
- Check: are figures self-contained? Caption = legend.

### Step 5: Reviewer Check

- Read the paper as if you were a tired, skeptical reviewer
- What would you criticize? Fix it before submission.
- Is there a clear gap statement? Is the contribution obvious?

### 🔴 STOP — User Confirmation Required

**Pause and confirm with the user:** Does the Introduction's gap statement match the Results you actually obtained? Did you change any experiment, analysis, or finding during writing?

| User Says | Action |
|-----------|--------|
| "No" to gap match / "Yes" to changed findings | → **Return to Layer 1**, revise Reader Analysis Worksheet and gap statement before touching prose |
| "Yes" to gap match / "No" to changed findings | → Proceed to next workflow |

> 🔁 This checkpoint loops back to Layer 1 whenever gap and results diverge. A mismatch is the #1 cause of reviewer rejection (bait-and-switch — see Workflow 4).

## Workflow 2: Revising an Existing Draft

> **Input**: Existing draft (full or partial)  
> **Output**: Revised draft with strategic alignment + energy/flow/paragraph fixes applied

> "Revision is the key to strong scientific writing. You cannot revise effectively on screen. Print the draft and edit with a pencil." — Alley, L10
>
> "Writing is rewriting. The first draft is the author talking to themselves; the second draft is the author talking to the reader." — Lebrun (paraphrased)

Use when the user has a complete or partial draft that needs improvement.

> **Multi-round revision:** Most papers need 3-5 revision cycles, not one. Each pass targets a different layer. The structure below documents one complete cycle (Passes 1-4), but plan to run the full cycle at least twice. Between cycles, put the paper aside for a day — distance reveals problems invisible during continuous editing. Track which passes find the most issues; overweight those in the next cycle.

### Pass 1: Strategic Audit (Lebrun)

1. **Audience check**: Does the paper match the target journal's readers? Is the language appropriate for their expertise level?
2. **Halo check**: Does the introduction create a positive first impression? (No trivial opening, no question-starting, no "In recent years...")
3. **Gap check**: Is the knowledge gap explicitly stated? Can the reader understand why this work matters?
4. **Promise check**: Does the paper deliver what the introduction promises? (No bait-and-switch.)
5. **Limitation check**: Are limitations acknowledged before the reader thinks of them?

### Pass 2: Energy Audit (Alley)

1. **Verbs**: Are there hidden nominalizations? (made an analysis → analyzed; performed an investigation → investigated)
2. **Nouns**: Are there noun strings longer than 3 words? Break them up.
3. **Deadwood**: Cut "due to the fact that," "in order to," "it is important to note that," etc.
4. **Passive voice**: Is it used appropriately? (Needed for "the patient was treated" but not for "the experiment was conducted.")

### Pass 3: Flow Audit (Alley + Lebrun)

1. **Topic position**: Does each sentence begin with familiar/known information?
2. **Stress position**: Does each sentence/new paragraph/section end with the most important point?
3. **Transitions**: Are logical relationships signaled explicitly? (however, therefore, for example, in contrast)
4. **Sentence openers**: Do they vary? Do they orient the reader?

### Pass 4: Paragraph Audit

1. **Unity**: Does each paragraph develop exactly one idea?
2. **Length**: Are paragraphs under 10-12 lines? Can long paragraphs be split?
3. **Topic sentence**: Does each paragraph start with a clear topic sentence that states the main point?
4. **Progression**: Does the paragraph follow topic→stress progression internally?

### 🔴 STOP — User Confirmation Required

**Pause and confirm with the user:** Did any Pass expose a structural problem? (e.g., Pass 1 found the gap statement is missing; Pass 2 found the Introduction promises X but Results deliver Y.)

| User Says | Action |
|-----------|--------|
| "Yes" — structural problem found | → **Return to Layer 1**, revise Reader Analysis Worksheet, rewrite affected sections, then re-run the audit |
| "No" — all passes passed | → Proceed |

> 🔁 This checkpoint prevents wasted effort: fixing sentences before fixing structure is ineffective (see "Failure Mode 4" in Boundaries).

## Workflow 3: Abstract Writing/Checking

> **Input**: Completed paper manuscript
> **Output**: Polished abstract following four-sentence structure (Background → Gap → Approach → Result)

> "The abstract is the most-read part of any paper. It should answer four questions in four sentences: What is known? What is unknown? What did you do? What did you find?" — Lebrun, SW3 Ch14

### Structure (Four-Sentence Template)

| Sentence | Job | Example Opener |
|----------|-----|----------------|
| 1 | What is known (background) | "Recent advances in X have shown..." |
| 2 | What is unknown (gap/problem) | "However, it remains unclear whether..." |
| 3 | What you did (approach) | "Here we show / We developed / We analyzed..." |
| 4 | Key result + significance | "We found that... These results suggest..." |

### Checklist

- [ ] Does the abstract stand alone (no figures, no references)?
- [ ] Can a non-specialist understand the background and gap?
- [ ] Is the key numerical result included?
- [ ] No "will be discussed" or "will be presented"?
- [ ] Written LAST (after the paper is complete)?

### Note on Structured Abstracts

Some journals (e.g., Nature Portfolio, BMJ, some clinical journals) require **structured abstracts** with explicit subheadings: Background, Methods, Results, Conclusion. The four-sentence logic stays the same — each subheading maps to one of the four functions above. When a journal mandates subheadings, simply distribute the content across the labeled sections while preserving the background → gap → approach → result flow.

### 🔴 STOP — User Confirmation Required

**Pause and confirm with the user** (the Abstract is written LAST): When writing the Abstract, is your key result hard to state in one sentence? Does the gap → approach → result chain flow logically?

| User Says | Action |
|-----------|--------|
| "Yes" to either (hard to state / doesn't flow) | → **Return to Layer 1**: the knowledge gap or contribution isn't well-defined yet. Fix strategy before polishing abstract prose |
| "No" — flows clearly | → Proceed |

> 🔁 A hard-to-state result signals a strategy problem, not a wording problem.

## Workflow 4: Introduction Writing/Checking

> **Input**: Reader Analysis Worksheet, clear results/methods, 2-3 target journal sample papers
> **Output**: Polished introduction with explicit gap statement and halo-effect-aware opening

<!-- Sources: Lebrun SW3 Ch16 (halo effect), Alley L7 (roadmap) -->

### Structure

```
P1: Broad context — what is known and why it matters
P2: Specific background — what specific work has been done
P3: The knowledge gap — what is missing / unresolved / controversial
P4: Your approach — how you address the gap
P5: Your contribution — the key finding (optional, depending on journal style)
```

### Checklist

- [ ] First sentence is specific, not trivial (NOT "In recent years..." or "X is an important...")
- [ ] Gap statement is explicit, not buried
- [ ] **Reader motivation established** (SW3 Ch7) — does the reader immediately see why this matters? Does the opening convey novelty and relevance, not just context?
- [ ] Literature is synthesized, not listed (NOT "Author A found X, Author B found Y")
- [ ] Introduction accounts for halo effect — positive first impression
- [ ] Introduction manages confirmation bias — acknowledges counter-arguments
- [ ] Ending leads logically to the approach/methods
- [ ] Introduction is < 25% of total paper length

### 🔴 STOP — User Confirmation Required

**Pause and confirm with the user** (the Introduction is the most sensitive section to strategy-craft misalignment):

1. Does the gap statement lead logically to your methods?
2. Does the literature review support (not contradict) your framing?
3. Does the first paragraph sound specific (not trivial)?

| User Says | Action |
|-----------|--------|
| "No" to Q1 | → **Return to Layer 1** and sharpen the gap |
| "No" to Q2 | → **Return to Layer 1** and adjust contribution framing |
| "No" to Q3 | → Check Reader Analysis Worksheet: did you overestimate what readers already know? Adjust the opener |

> 🔁 Fix strategy before rewriting prose (see "Failure Mode 4" in Boundaries).

## Workflow 5: Sentence-Level Audit (Universal)

> **Input**: Any section of scientific text (paragraph or longer)
> **Output**: Polished text with energy/flow/length/precision improvements applied

Apply to ANY sentence in a scientific paper:

### Precision Check
- [ ] Are modifiers placed next to what they modify?
- [ ] Does each pronoun have a clear antecedent?
- [ ] Is the denotation correct (word means what you think it means)?
- [ ] Is parallelism grammatically and logically consistent?

### Energy Check
- [ ] Is the main verb strong and active? (→ no nominalizations)
- [ ] Are there unnecessary noun strings? (→ break up with prepositions)
- [ ] Is every word doing work? (→ cut deadwood)

### Flow Check
- [ ] Does the sentence start with familiar/known info?
- [ ] Does the sentence end with the new/key info?
- [ ] Is the relationship to the previous sentence signaled? (transition)

### Length Check
- [ ] Is the sentence under 25-30 words? (→ split if longer)
- [ ] Is the idea complex? (→ use shorter sentences for complex ideas)

### Acronym Audit
- [ ] Every acronym defined at first use (and only at first use)
- [ ] No acronym used fewer than 5 times in the paper (→ remove and spell out)
- [ ] No more than 5 acronyms total (→ create an abbreviation table if more)
- [ ] No single acronym used for two different terms
- [ ] Acronyms are standard in the field (if not, prefer a short synonym over introducing a new one)

### Gunning Fog Index (Optional Quantitative Check)

Alley recommends the **Gunning Fog Index** as a readability diagnostic. Calculate for any paragraph that feels dense:

```
Fog Index = 0.4 × [ (words / sentences) + 100 × (complex words / words) ]
```

where complex words = words with 3+ syllables (excluding proper nouns, compound words, and -es/-ed suffixes).

- **Target for scientific writing:** 12–15
- **Above 17:** The paragraph is too dense — shorten sentences, simplify vocabulary, or split the paragraph
- **Below 10:** May be oversimplified (check for lost nuance)

> ⚠ Diagnostic only, not a target to minimize. Bundled calculator: `python3 references/fog-index.py "<paragraph>"`.

### 🔴 STOP — User Confirmation Required

**Pause and confirm with the user:** Are multiple sentences across a section failing the same Energy or Flow check? (Warning sign: fixing the same pattern — passive voice, missing transitions — across 3+ consecutive paragraphs.)

| User Says | Action |
|-----------|--------|
| "Yes" — systematic failure | → First **revisit Layer 2 (Craft)** to check if the right pattern is being applied. If still failing → **return to Layer 1**: the section's strategy (audience, purpose, structure) may be wrong |
| "No" — isolated fixes | → Continue polishing; no structural issue |

> 🔁 No amount of sentence polishing fixes a wrong strategy.

## Workflow 6: Title Writing/Checking

> **Input**: Completed paper + one-sentence contribution statement
> **Output**: Searchable, precise, honest title meeting all checklist criteria

<!-- Source: Alley ("title is the single most important phrase") -->

### Structure: Two Criteria for a Strong Title

| Criterion | Question | How to Test |
|-----------|----------|-------------|
| **Identifies the field** | Does the title place the work in its field of study? | Would a reader know the general area from the title alone? |
| **Separates from others** | Does the title distinguish this work from all others in the field? | How does it read in a list of titles from a computer search? |

### Checklist

- [ ] **Field identified** — the title names the field of study (not too broad, not too narrow)
- [ ] **Distinctive detail** — includes the unique element (specific method, material, finding) that sets this work apart
- [ ] **3-4 details maximum** — beyond that, the title blurs; push secondary details to summary/introduction
- [ ] **Short words as "rest stops"** — intersperse short words (to, a, in, the, of, for) among technical terms; avoid strings of big words
- [ ] **No unrecognized acronyms** — if readers outside your subfield won't recognize it, spell it out or rephrase
- [ ] **Promises what the paper delivers** — no exaggeration, no mismatch between title promise and results
- [ ] **Searchable** — includes keywords that someone searching the literature would use
- [ ] **Reads well in a search result list** — the reader can judge relevance from the title alone

### Revision Test

Read the title in a simulated search results list (three other related titles). Would a researcher pick yours? If not, the title needs work.

**Case example:** Alley describes a proposal titled "A New Heat Transfer Fluid for the Solar Receiver at the Barstow Power Plant" — it overwhelmed readers with details. The revision: "A New Heat Transfer Fluid for Solar One: Using Oil to Improve the Performance of the World's Largest Solar Power Plant" — shorter, with "world's largest" as the distinctive hook.

### 🔴 STOP — User Confirmation Required

**Pause and confirm with the user:** Is the title hard to write? Can you summarize the paper in one short phrase?

| User Says | Action |
|-----------|--------|
| "Yes" (hard to write) or "No" (can't summarize) | → **Return to Layer 1**: the contribution isn't well-defined. Sharpen your one-sentence contribution before returning to the title |
| "No" (title is clear) | → Proceed |

> 🔁 The title is a proxy for strategy clarity. A hard-to-write title means the strategy isn't ready — it's never just a wording problem.

## Workflow 7: Conclusion Section Writing/Checking

> **Input**: Completed paper (Introduction, Results, Discussion sections)
> **Output**: Polished conclusion aligned with Introduction's question

<!-- Sources: Alley (closure, analysis, future perspective), Lebrun (answer intro question, no new claims) -->

### Structure

```
P1: Summary of key finding(s) — revisit the contribution in light of the full results
P2: Implications — what does this mean for the field? For practice?
P3: Limitations — acknowledged proactively (builds credibility)
P4: Future work — specific, testable next steps
```

### Checklist

- [ ] **Answers the question posed in the introduction** — the conclusion connects back to the gap statement; there is one clear thread from intro → results → conclusion
- [ ] **No new claims** — every statement in the conclusion is supported by evidence already presented in the results/discussion
- [ ] **Key finding repeated in stress position** — the most important result appears at a paragraph end or as the section's closing statement
- [ ] **Limitations acknowledged** — stated before the reader thinks of them; framed as opportunities, not failures (SW3 Ch17)
- [ ] **Implications are specific** — not "these findings have important implications" but "these findings suggest that X should be reconsidered in Y context"
- [ ] **Future work is concrete** — not "more research is needed" but "a controlled trial comparing A with B would determine whether..."
- [ ] **No redundancy with abstract** — the conclusion adds synthesis and reflection; it does not re-state the abstract
- [ ] **Proportionate length** — conclusion is typically 5-10% of total paper length (shorter than introduction)

### Counter-Example: What Not to Do

| Trap | How to Spot | Fix |
|------|-------------|-----|
| **Introducing new data** | A table or result appears here that was not in the Results section | Move it to Results or remove |
| **Overclaiming** | "This proves that..." when the evidence is correlational | Hedge appropriately: "This suggests that..." |
| **Generic limitations** | "Sample size was small" without explaining how it affects interpretation | State the specific impact and how future work addresses it |
| **False closure** | Ending that just stops without synthesis | Add one sentence reflecting on the broader meaning |

### 🔴 STOP — User Confirmation Required

**Pause and confirm with the user:** Does the Conclusion answer the question posed in the Introduction? Or are you addressing a different question than the one promised?

| User Says | Action |
|-----------|--------|
| Different question | → **Return to Layer 1**: either update the Introduction's gap statement, or update the contribution in the Reader Analysis Worksheet and revise the Introduction accordingly |
| Same question — aligned | → Proceed |

> 🔁 The Conclusion must answer the Introduction's question. Mismatch means the Introduction promised one thing but the paper delivered another.

## Pre-Submission Final Checklist

Use this **after** all workflows are complete, immediately before submission. It integrates strategy-level and craft-level checks into one pass.

### Strategy Integrity
- [ ] **Gap-contribution alignment** — Does the Introduction's gap statement lead directly to your approach? Does the Conclusion answer the question posed in the Introduction?
- [ ] **Promise kept** — Does the paper deliver exactly what the title + abstract promise? No bait-and-switch.
- [ ] **Journal fit** — Does the paper match the target journal's scope, audience, and format conventions?
- [ ] **Reader already persuaded** — Read as a tired reviewer: would you recommend acceptance or rejection? Fix the top three weaknesses before submitting.

### Structure
- [ ] **Introduction ≤ 25%** of total paper length
- [ ] **Conclusion 5-10%** of total paper length (shorter than Introduction)
- [ ] **Figures placed near their first mention** (same page spread)
- [ ] **Each paragraph begins with a topic sentence** and develops one point
- [ ] **Headings alone reveal the paper's organization** (the TOC test — see Headings Design)

### Craft
- [ ] **Energy audit complete** — All nominalizations fixed? Deadwood removed? Active voice default?
- [ ] **Flow audit complete** — Each sentence begins with familiar info? Stress positions carry key points?
- [ ] **Sentence audit complete** — All sentences under 30 words? No ambiguous "this" or vague references?
- [ ] **Acronym audit complete** — ≤5 acronyms, each defined at first use, each used 5+ times?
- [ ] **Abstract standalone** — No figures, no references, key numerical results included.

### Production
- [ ] **Format matches journal guidelines** (font, margins, line spacing, reference style)
- [ ] **Figures at required resolution** (check journal's author instructions)
- [ ] **Cover letter prepared** (connects work to journal's readers)
- [ ] **All co-authors have approved the final version**
- [ ] **Spell-check run** (on the final, formatted version — last edit always introduces new typos)

## Grammar / Punctuation / Usage Quick Reference

> Condensed from Alley's appendices (4Ed Appendices A–C). Use this when diagnosing specific sentence-level errors beyond the general Sentence Audit.

### Grammar (Appendix A)

| Error | Example | Fix |
|-------|---------|-----|
| **Subject-verb disagreement** | "The set of experiments **were** conducted" | "The set **was**" (subject = set, not experiments) |
| **Unclear pronoun reference** | "The receiver presented the radiometer with a high-flux environment, so **it** was mounted in a steel container" — what does "it" refer to? | Repeat the noun: "…so **the radiometer** was mounted…" |
| **Faulty parallelism** | "…can develop rashes, sores, and **may leave the area**" | "…rashes, sores, and **wandering tendencies**" (all nouns) |
| **Dangling modifier** | "**To determine the flux**, the probe was inserted" — who determined? | "**To determine the flux**, we inserted the probe" |
| **Vague "this"** | "**This** shows that…" without a following noun | "**This result** shows…" or "**This discrepancy** shows…" |

### Punctuation (Appendix B)

| Rule | Correct | Incorrect |
|------|---------|-----------|
| **Comma after introductory phrase** | "**After heating the sample,** we measured the temperature" | "After heating the sample we measured the temperature" |
| **Comma in a series** | "oxygen, nitrogen, **and** argon" (Oxford comma) | "oxygen, nitrogen and argon" (ambiguous if last two are grouped) |
| **Comma with FANBOYS** | "The voltage dropped, **and** the current increased" | "The voltage dropped and the current increased" (comma before coordinating conjunction joining independent clauses) |
| **Restrictive vs nonrestrictive** | "The probe **that** was coated with gold failed" (restrictive — no comma) vs "The probe, **which** was coated with gold, failed" (nonrestrictive — commas) | Using "which" without commas for restrictive clauses; using "that" with commas |
| **Semicolon** | "The first trial failed; **however,** the second succeeded" | "The first trial failed, however, the second succeeded" (comma splice with conjunctive adverb) |
| **Colon** | "Three factors were considered: cost, time, and safety" | Colon after a verb fragment: "Three factors **were**: cost, time, and safety" |

### Usage (Appendix C)

| Common Error | Correct |
|--------------|---------|
| **affect** (verb: to influence) vs **effect** (noun: result; verb: to bring about) | "The temperature **affected** the rate" / "The **effect** was significant" |
| **that** (restrictive) vs **which** (nonrestrictive, with comma) | "The sample **that** was contaminated was discarded" (specific) / "The sample, **which** was contaminated, was discarded" (incidental) |
| **fewer** (countable) vs **less** (uncountable) | "**Fewer** participants" / "**Less** time" |
| **compose** vs **comprise** | "The whole **comprises** the parts" / "The parts **compose** the whole" (not "comprised of") |
| **continually** (regular intervals) vs **continuously** (without interruption) | "We **continually** measured the temperature" (regularly) vs "The pump ran **continuously**" (non-stop) |
| **principal** (main, primary) vs **principle** (fundamental truth) | "The **principal** investigator" / "The **principle** of conservation" |
| **ensure** (make certain) vs **insure** (protect financially) | "**Ensure** the sample is heated" / "**Insure** the equipment" |

## Boundaries (When NOT to Use This Skill)

### Failure Modes to Watch For

| # | Trap | Symptom | If-Then |
|---|------|---------|---------|
| 1 | **Over-application of rules** | Fixing every passive voice without considering context | If editing passive voice → ask: is the receiver more important than the actor? If yes → keep passive. If no → convert to active. |
| 2 | **Formulaic writing** | Every abstract or introduction looks structurally identical | If template feels forced → ask: does the content demand a different structure? If yes → deviate from the template. The four-sentence abstract is a guideline, not a formula. |
| 3 | **Ignoring venue differences** | Applying Nature-style conventions to a PLOS ONE submission | If adapting for a new venue → research that journal's conventions explicitly. Match the target, don't copy from a different journal. |
| 4 | **Revision without strategy** | Polishing sentences before the paper's structure is sound | If user requests sentence polish → check strategy first: is the gap defined? Does the intro match the results? If no → fix strategy before polishing prose. |
| 5 | **Over-condensing** | Cutting words changes the meaning or loses necessary nuance | If reducing word count → test: does removing this word change the meaning? If yes → keep it. Precision > brevity. |

### When NOT to Use

| Scenario | Redirect To |
|----------|-------------|
| User wants non-scientific writing (fiction, journalism, marketing, creative writing) | → Use a domain-specific writing skill (not this one) |
| User only needs formatting/LaTeX help without content revision | → Use a formatting/LaTeX skill |
| User needs field-specific terminology advice | → Use domain-specific resources (textbook, glossary, field handbook) |
| User needs translation between languages | → Use a translation skill |

### Limitations of the Source Books

- Both books focus primarily on English-language STEM publishing; some principles may not transfer to humanities or non-English journals
- Neither book addresses AI-assisted writing tools or LLM workflows
- Neither book addresses code/data papers, preprints, or open-access publishing strategy in depth
- Alley's examples skew toward engineering; Lebrun's toward biomedical
- The four-sentence abstract template may not fit all journal formats (e.g., some Nature journals have structured abstracts)
